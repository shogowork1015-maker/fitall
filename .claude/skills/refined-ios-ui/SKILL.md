# 洗練されたiPhoneアプリ風UIの作り方（Limitless App）

お手本は「カシカリ帳」（SwiftUI製の貸し借り記録アプリ）。あのアプリが洗練されて見える理由を分解し、
Next.js（Web）で同じ水準を出すための規則にしたもの。**見た目の部品を真似るのではなく、理由を真似る。**

## 0. まず画面の「設計」を決める（ピクセルより先）

画面を作る前に、必ず次の3つを1行ずつ書き出す。書けない画面は作らない。

1. **この画面に来る理由**（例：チケット画面＝あと何回あるか確かめて、足りなければ買う）
2. **主役**：いちばん大きく見せるものを1つだけ（例：残り回数「2回」）
3. **主な操作**：黒い大きなボタンは1画面に1つだけ（例：「予約する」）

ほかの要素はすべて主役と主な操作を支える脇役。脇役は小さく、灰色で、下に置く。

## 1. カシカリ帳が洗練されて見える理由

| 理由 | 具体的にやっていること |
|---|---|
| iOS純正の部品をそのまま使う | 大きな左寄せ見出し（Large Title）、灰色の地に白い角丸のまとまり（Inset Grouped）、黒い丸型の切替、下から出るシート |
| 文字の強弱がはっきり | 主役の名前・金額は太く大きく（20〜34pt）、補足は小さく灰色（13〜15pt）。中間の大きさを作らない |
| 色は意味にだけ使う | 白・黒が基本で、ブランド色は1色だけ。**絶対に区別すべき1軸**（Limitlessでは「対応が必要か」）にだけ色を使う |
| 1画面の要素が少ない | 1行に載る情報は「名前・金額・日付」程度。説明文を画面に書かない |
| 数字が主役 | 金額は右に揃えて太字。単位（円・回）は小さく |
| 一貫性 | 同じ種類の情報は全画面で同じ部品・同じ位置 |

## 2. やってはいけないこと（AIっぽさ・ウェブっぽさの原因）

- **ラベル風の飾りは一切使わない**（オーナーの明確な指示）：「確」「待」のような1文字の札、状態を示す小さな枠付きラベル、行の左端の色帯、状態を示す色の点。状態は文字そのもの（「承認待ち」）か、行や面全体の塗り（アクア／黒）で示す
- **丸で囲んだアイコンボタンは使わない**：見出し横の歯車や「＋」は記号だけを置く（タップ領域44ptは保つ）。右下に浮く丸い「＋」ボタンも使わない
- 意味のない装飾：頭文字の丸アイコン、淡い色の札（バッジ）を多用、色付きアイコンの羅列、グラデーション、光る影
- 全部をカードで囲んで縦に並べる（「見出し＋カード」の繰り返し）
- 逆に、全部の枠を消して文字だけを並べる（まとまりが消えて羅列に見える）
- 黒い大きなボタンを1画面に2つ以上置く
- 画面に説明文を書く（「ここで設定した〜を使って〜します」など）。必要なら1行の注記を一番下に
- 16px前後の中途半端な文字サイズを多用して強弱をなくす
- 開発用の注記（確認モードなど）を画面の上に目立たせる

## 3. 寸法と色（src/ui/tokens.css が正）

- 地色：`#F2F2F7`（iOSのグループ背景）／まとまり：`#FFFFFF`、角丸12px、影なし
- 文字：本文 `#000`、補足 `#6E6E73`、無効・矢印 `#C7C7CC`、区切り線 `rgb(60 60 67 / 18%)` 0.5px
- 主な操作の色（ティント）：黒 `#111`。アクア `#12C7BE` は面（塗り）としてだけ使い、上の文字は必ず黒。アクアの文字は白地では読めないので使わない
- **色は白・黒・Limitlessのアクア `#12C7BE` の3つだけ**（灰色は黒の薄い段階として補足文字と区切り線にだけ使う）。オレンジ・緑・赤などの状態色は使わない。対応が必要なもの（承認待ちなど）はアクアの面で目立たせる。エラーだけは例外的に赤 `#D70015` の文字を許す
- 文字の段階：大見出し34/700、見出し22/700、項目17/600、本文17/400、補足15/400、注記13/400（13未満は使わない。タブの文字だけ10）
- タップ領域44pt以上。大きいボタンは高さ52の丸型（角丸999）

## 4. 部品（src/ui/ にある。新しい画面はこれだけで組む）

採用したのは「A案：タイムライン型」。見本の画像は `design/mockups/`（trainer-screens.png / customer-screens.png）。
新しい画面は、まず見本と同じ作り方で画像を描いてから実装する。

- `Screen`：白い画面。上に小さな補足（日付・件数）か戻るリンク、その下に大きな見出し（34/800）
- `IconLink` / `IconButton`：見出し横の記号だけのボタン（丸で囲まない）
- `Card` 一式：黒い面。その画面の主役を1つだけ置く（次のセッション・チケット・声をかけるべき人）
- `TicketCard`：黒い面に残り回数を大きく、穴（残り＝アクア、予約済み＝アクアの輪、使用済み＝薄い丸）
- `Timeline` / `Slot` / `Gap`：時刻・縦線・予約の面。空き時間も書く。対応が必要な予約だけアクア
- `Week`：週の帯。選んだ日だけ黒く塗る
- `DateList` / `DateRow`：日付を左に大きく置く一覧
- `Hero` / `Bars` / `Stats`：大きな金額、6か月の棒（今月だけアクア）、数字3つの帯
- `Section`：大きな見出し（title）か小さな灰色の見出し（header）。`group` で薄い灰色の面に束ねる（設定アプリの形）
- `Row`：面の中の1行。`action` を付けるとアクアで塗る
- `Button`：黒（1画面に1つ）、アクア（黒い面の上）、薄い灰色、赤い文字。`Buttons` で左右に余白を取って並べる
- `Segmented`・`Sheet`・`TabBar`：黒い丸型の切替、下から出るシート、下部タブ

## 5. 画面を作ったら確認すること

1. スマホ幅（375×812）でスクリーンショットを撮り、「主役」が最初に目に入るか
2. 黒いボタンが1つだけか
3. 装飾（§2）が入っていないか
4. 文字が13pt以上、タップ領域が44pt以上か
5. 読み込み中・エラー・データなしの表示があるか
